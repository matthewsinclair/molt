## Notes

Three sleeves in daily use: rhadamanth and gyges on macOS, kovacs on Ubuntu in Parallels; farcaster and pihole are Pis with a small stack. `molt upgrade` = pull and fast config sync; `molt resleeve` = the sync without the pull; `molt maintain` = heavy system maintenance. `envsubst` only substitutes `MOLT_*` variables. `VERSION` is the single source of truth for the version number: 0.2.0 since 22 Oct, cut by bumping `VERSION`, closing the changelog's Unreleased section under the version and date, and an annotated tag `v<version>` pushed with main. Since 22 Oct `molt_error` writes to stderr and every other level to stdout, and a `git pull` that fails anywhere in `molt upgrade` or the bootstrap shows git's reason and fails the run at the end; only a branch with no upstream is a skip.

A sleeve takes the managed floor when its manifest enables a `sysadm` agent and its `vars.sh` declares `MOLT_CLAUDE_CONFIG_DIR`: `molt upgrade` then asks for sudo once to install `managed-settings.d/molt-sysadm.json` beside a sidecar it writes first, and the floor binds every Claude Code session on the sleeve, hv's included. A Linux sleeve whose manifest enables an `ops` or `docs` agent, and whose distro ships `bwrap-userns-restrict`, takes Molt's copy of that AppArmor profile the same way, the distro's kept beside it as `.molt-orig`; it is a dpkg conffile, so keep Molt's copy at the prompt and let `molt upgrade` re-check it. Elsewhere Molt renders neither, removes only a file whose sidecar it wrote, and doctor's checks 14 and 15 pass as none needed. Three agent kinds, three naming schemes: sleeve `<hostname>-<role>`, project `<project>-<suffix>`, estate `<estate>-estate`; an estate session must start in or below the directory holding the deployed `.claude/`, since Claude Code loads from the launch directory and its parents, never a child. The per-instance files a sleeve may carry are in `docs/guides/templates.md`'s table: keyd's config, ssh fragments, the dock favourites and, since 22 Oct, the GNOME keys in `instances/<host>/desktop/gsettings`.

A rendered file is re-rendered when the digest of its inputs no longer matches the `.molt-rendered` sidecar, and since 21 Oct the sidecar also records the digest of what molt wrote, so only a hand edit is backed up. A builder's pre-commit gate runs `intent doctor` at the committed head in its worktree, so a whiteboard view a verb re-rendered must be committed with that verb's event, by its owner, and every node commits its own `board.json` with every commit, since an inbound ask lives there. Commit ids from before 20 Oct may be stale after the AI-attribution purge; `intent/ref/2026-10-20-history-purge-commit-maps.md` translates them.

The `backup` liberator observes; it never mounts, attaches or configures. `backup_verify` exits 2 when the share-side checks could not run, which is the normal state. `recentRuns` records finished runs only.
