## What happens

When the user repo has a static `config/ssh/config` and no `config/ssh/config.tmpl`, `ssh_install` installs it through `molt_install_config`, which calls `molt_link` and symlinks `~/.ssh/config` to the repo file. But `ssh_check` (liberators/ssh.sh, "is a symlink (sshd requires regular files)") and `ssh_verify` ("VERIFY FAIL: ~/.ssh/config is a symlink") both refuse a symlinked `~/.ssh/config`. So the static path can never settle: install links, check calls it a fault, and the next install links it again. sshd itself requires a regular file there.

On main at 35b3670, any config.d fragments were also appended through the link into the user repo's own `config/ssh/config`. Issue 0024's branch (issue-0024, 7f7f41d) stops that: fragments with no template now fail check and install. The static path without fragments still links as before.

Molt-matts has both `config/ssh/config` (9 Mar 2026) and `config/ssh/config.tmpl` (4 Sep). `molt_install_config` picks the template when both exist, so the static file there is never used.

## Fix (not made; vc to queue)

The static path should copy the file into place as a regular file, mode 600, or refuse up front, naming the template it needs, rather than link a file the liberator's own check and verify refuse. Molt-matts's unused static `config/ssh/config` should go, as a change to that repo.
