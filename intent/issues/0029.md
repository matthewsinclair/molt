## What happens

`molt_render_place` (`lib/molt.sh:588-593`) backs up every file molt itself rendered whenever the new render's content differs from the file on disk, and warns `Rendered file changed since last render, backing up: <target> -> <target>.molt-backup.<stamp>`. The sidecar `<target>.molt-rendered` carries only the digest of the render's inputs (`lib/molt.sh:632`, read at `:780`), so the check cannot tell a hand edit of the rendered file from a change to the template that produced it, and treats both as the first.

## Seen

21 Oct 2026, Molt-matts d48886f -> 45e344c, which changes the ops/docs `settings.json.tmpl` and the three role `AGENTS.md.tmpl`. `molt resleeve` on rhadamanth and `molt upgrade` on kovacs each left five backups in the agent homes: `AGENTS.md.molt-backup.<stamp>` in all three homes and `.claude/settings.json.molt-backup.<stamp>` in ops and docs. On rhadamanth, `diff` of each backup against the current file shows only 45e344c's changes: nobody edited the rendered files, and the warning says they changed.

## Why it matters

- The warning asserts a fact Molt did not check. The rendered file did not change since last render; the render did.
- Every template change leaves a `.molt-backup.<stamp>` file in every agent home (and in `~/.ssh`, `~/.config/claude`, every rendered target), for the life of the sleeve. The homes are the places ST0006 exists to keep clean; `molt doctor` and `molt agent list` say `current` over a home that is accumulating files.
- The backup is only useful in the case the check cannot see: a hand edit to a file molt will overwrite. Today it fires in the other case, so the one that matters is drowned.

## Expected

The sidecar records the digest of what molt wrote as well as of what it read. At place time: on-disk file matches the recorded output digest means molt's own untouched render, so replace it with an info line and no backup; it differs means a hand edit, so back up with the warning, which is then true. The first render after this change has no output digest, so it backs up once, as now. Backups of regular files molt did not render (`lib/molt.sh:604`) are unchanged, so WP04's B5 line for `~/.config/claude/settings.json` still appears.

## Where

`lib/molt.sh`: `molt_render_place` around 588-610, the sidecar writer at 632 (and the chmod at 639), the reader at 780 (`sed -n 's/^digest //p'`, which an added `output <sha>` line must not disturb). `test/templates.bats` pins the render paths. Related: the WP02 agents liberator renders through `molt_render`, so no change there.
