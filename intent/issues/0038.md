Found on rhadamanth's move, 23 Oct 2026 (ST0006 WP04, vc on the bounce).

The move takes `~/.claude` to the declared config dir whole, but a value inside the moved `settings.json` that names a file under `~/.claude/` by absolute path still names the old place afterwards. rhadamanth's user settings carried a PreToolUse hook on Bash, `python3 /Users/matts/.claude/hooks/rg-replace-guard.py`, hand-installed in August and managed by nothing. The script moved with the state; the line did not. python3 exits 2 when it cannot open its script, and exit 2 from a PreToolUse hook blocks the call, so every Bash call in every session on the sleeve was refused until vc repointed the line at 06:20Z. hv is removing that hook (no shipped Python; the guard is not coming back as Python).

kovacs moved clean because its settings named nothing under `~/.claude/`. gyges has not moved, and its settings are unchecked.

What the fix needs:

- The move rewrites, in the `settings.json` it moves, every string value that names a path under `$HOME/.claude/` to the same path under the config dir, and names each value it rewrote. The files moved, so the move owns the paths that point at them.
- `molt doctor`'s claude check names, on a sleeve that declares a config dir, any value in the user settings that still points under `$HOME/.claude/`, with its key.
- A test moves a fixture whose settings carry a hook command and a statusLine command naming `~/.claude/` by absolute path, and finds both rewritten; doctor flags one planted after the move.

gyges' move (the WP04 runbook's gyges section, carried on vc's board as todo 5) waits on this.
