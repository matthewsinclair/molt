## What happens

`molt doctor`'s enabled-liberators step prints `not installed: <libs>` and then, under it, the first three lines of each failing liberator's check output, each prefixed with the liberator's name. Those lines already carry molt's own prefix and the liberator's name, because the checks print through `molt_info`, `molt_warn` and `molt_error`, so each line reads `claude: Zen: claude: <report>`, or `agents: Zen: agents: <name>: <file> is missing`. The name appears twice and molt's `Zen` marker sits in the middle of the line.

## Repro (main at 929487d)

On any sleeve whose enabled liberator's check fails, eg before `molt upgrade` has rendered the agent homes:

```
molt doctor
...
[6/13] Enabled liberators... 15/16 installed
         not installed: agents
         agents: Zen: agents: kovacs-sysadm: ~/Devel/agt/kovacs-sysadm/AGENTS.md is missing
         agents: Zen: agents: kovacs-sysadm: ~/Devel/agt/kovacs-sysadm/CLAUDE.md is missing
         agents: Zen: agents: kovacs-sysadm: ~/Devel/agt/kovacs-sysadm/.claude/settings.json is missing
```

`docs/guides/sleeve-agents.md` (ST0006 WP05) describes the line as it prints today and cites this issue.

## Cause

`lib/molt.sh`, the loop at about line 1396 in `cmd_doctor`: `not_installed_why="${not_installed_why}         ${lib}: ${line}"` for each of `head -3` of the captured `liberator_load` plus `liberator_check` output. The capture holds molt's prefixed lines, and the liberator's name is added again.

## Fix

Print each captured line indented as it is: molt's prefix already names the liberator, and a line without it (a `liberator_load` failure, or a bare `echo` in a check) still names its liberator through the `not installed:` line above. Keep the three-line cut. One test in `test/molt.bats` pinning the shape of a failing liberator's lines under doctor. Severity low: the information is all there, read twice.
