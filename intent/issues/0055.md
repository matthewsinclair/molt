cmd_doctor counts each check that does not pass and closes with "N of M checks did not pass", but the summary echo is its last statement, so `molt doctor` exits 0 whatever failed. A caller that reads the exit sees success over a failing check. ST0008's design already says doctor fails on an unknown tree.

Fix: doctor exits 1 when any check did not pass, and 0 only when all passed. The closing line and the exit come from one function, so they cannot disagree.

Callers that read doctor's exit (surveyed 24 Oct):
- test/molt.bats "molt doctor runs without crashing" asserted success. It changes: the run's exit must match its closing line.
- No other test, bin/molt verb, guard, CI workflow, Molt-matts script or doc chains on it with && or reads its exit.
- People and agents who run `molt doctor` see a non-zero exit where a check fails: a shell prompt's status mark, or a Claude Bash tool's "Exit code 1".
