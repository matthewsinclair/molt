## What is wrong

Molt implements devbin's dev/opt/brew contract a second time, in its own code, and Gtools' copy is modelled on it:

- `lib/install.sh` (about 700 lines), sourced by `bin/molt` for `molt install`, `molt use` and `molt upgrade` (`cmd_install`, `cmd_use` and `cmd_upgrade`):
  - the runtime set (`molt_runtime_set`);
  - the manifest and its forms (T3: `molt_install_field`, `molt_install_form`, `molt_install_drift`);
  - the tree and its commit (T1 and T4: `molt_tree`, `molt_tree_commit`, `molt_version_line`);
  - the opt prefix (`molt_install_prefix`, from `--prefix` or the sleeve's declared prefix);
  - the switch and its shadow check (T5: `molt_switch_link`, `molt_served_tree`, `molt_path_shadow`).
- `test/install.bats` and `test/manifest.bats` (about 1150 lines), which prove that copy.
- `packaging/homebrew/molt.rb` has its own `def install` where devbin's T8 has one install body, `@@INSTALL@@`. Its caveats name `molt use dev`, `molt use opt` and `molt use brew`.
- `bin/.devbin/config.yaml` has no `install:` block, so `bin/devbin install` and `bin/devbin use` have no molt to publish or switch.

`molt install` and the tree functions also serve a sleeve's bootstrap (`bin/bootstrap.sh`) and the liberators, so this change reaches every sleeve. The plan reads each caller before anything moves.

## Fix outline

- Declare molt in an `install:` block: its opt prefix (the sleeve's, as `molt_install_prefix` reads it today, settled in the plan), its link (`molt: bin/molt`) and its runtime set as `files:` places.
- Remove `molt install` and `molt use`, with the publish, switch, shadow and manifest-writing code in `lib/install.sh` and the tests that prove that copy. The plan decides `molt upgrade` and what bootstrap and the liberators keep on reading them: a sleeve's bootstrap then calls `bin/devbin install` and `bin/devbin use` from the checkout.
- Keep molt's own `--version` reader, `molt_version_line`, which reads the manifest's `line` in opt and brew and HEAD in dev (T4 for a script tool).
- The formula installs through `@@INSTALL@@`, and its caveats name `bin/devbin use`, run in the checkout.
- The docs, the getting-started guide and CHANGELOG say the same, recording the removed verbs as a ruled divergence.

## Acceptance

- `molt install` and `molt use` are gone. `bin/devbin install` and `bin/devbin use dev|opt|brew`, run in Molt's checkout, publish and switch molt from devbin's one implementation, and a sleeve's bootstrap works through them.

- The formula renders from `@@INSTALL@@`, and its caveats name `bin/devbin use`.
