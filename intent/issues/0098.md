`cmd_new_user` (`lib/newuser.sh`) has two ways to end with exit 1 and nothing said. Both run under `bin/molt`'s `set -euo pipefail`. Both were measured on main on 5 Nov, with no output and nothing written.

- **A value flag given last, with no value after it.** Each of `--name`, `--email`, `--github`, `--hostname` and `--dest` is read as `x="${2:-}"; shift 2`, and on `dc/doctor-participant` so is `--from`. Given last, the `shift 2` fails. Measured: `molt new-user ada --name` and `molt new-user ada --dest` each exit 1.
- **A value not given, with nothing for its prompt to read.** Each value not given is prompted for with `[[ -z "$x" ]] && read -rp ...`, and at the end of stdin the `read` fails, as it does in a script run with no terminal. Measured with stdin from /dev/null: `molt new-user ada --email a@x.invalid --github ada --hostname h --dest <dir>`, which leaves out `--name`, a value with a default, exits 1. So does one that leaves out `--email`. The `email is required` and `hostname is required` checks after each prompt are never reached.

A first-run script that drops a value by mistake gets a failure with no reason. `cmd_install` (`lib/install.sh`) already refuses the first case, naming the flag: `[[ $# -ge 2 && -n "$2" ]] || { molt_error "--prefix needs a directory"; return 1; }`.

The change:
- Each of new-user's value flags, given with no value after it, is refused, naming the flag, and nothing is written. One check covers every value flag, not one per flag.
- A value not given, with nothing for its prompt to read, no longer ends molt. A value with no default, the user, `--email` or `--hostname`, is refused, naming what is missing. A value with a default, `--name` or `--github`, takes it, as Enter at the prompt does.
- An empty value that is given keeps the handling it has: `--from ""` is refused as no directory, and an empty `--name`, `--email`, `--github` or `--hostname` is asked for as a value not given is.

molt-vc found both in its review of issue 0097 on 5 Nov. It adds them to dc's 0093 to 0097 branch for 1.4.5, by hv's rule of 26 Oct that work found mid-release is fixed now.
