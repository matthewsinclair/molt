`cmd_new_user` (`lib/newuser.sh`) reads each of its value flags, `--name`, `--email`, `--github`, `--hostname` and `--dest`, and on `dc/doctor-participant` `--from` too, as `x="${2:-}"; shift 2`. Given last, with no value after it, `shift 2` fails, and under `bin/molt`'s `set -euo pipefail` molt exits 1 with nothing said. Measured on main on 5 Nov: `molt new-user ada --name` and `molt new-user ada --dest` each exit 1 with no output. A first-run script that drops a value by mistake gets a failure with no reason.

`cmd_install` (`lib/install.sh`) already refuses this case, naming the flag: `[[ $# -ge 2 && -n "$2" ]] || { molt_error "--prefix needs a directory"; return 1; }`.

The change:
- Each of new-user's value flags, given with no value after it, is refused, naming the flag, and nothing is written.
- An empty value that is given is not this case, and keeps the handling it has: `--from ""` is refused as no directory, and an empty `--name`, `--email`, `--github` or `--hostname` prompts, as a value not given does.
- One check covers every value flag, not one per flag.

molt-vc found it reviewing issue 0097 on 5 Nov, and adds it to dc's 0093 to 0097 branch for 1.4.5, by hv's rule of 26 Oct that work found mid-release is fixed now.
