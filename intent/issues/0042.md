Proposed by rhadamanth-sysadm on 23 Oct, for hv to rule. On 23 Oct the house's names moved from .lan to hockenbury.internal (Pi-hole host records; Tailscale split DNS and a search domain reach them from away). _zsh_generate_iterm2_ssh_colors (liberators/zsh.sh) writes each host's case pattern as <host>|<host>.lan|<host>.local. So `ssh gyges.hockenbury.internal` leaves the tab colour unchanged, and the next domain change means editing Molt. That is the only house domain Molt itself hardcodes (grep of lib, liberators, templates and bin, 23 Oct).

Proposal: Molt-matts declares the house domain(s) once at user scope, eg a [network] local_domains list. The generator adds <host>.<domain> for each one, and drops .lan and .local from code; if they are still wanted, they go in the list.

Related, and in Molt-matts rather than Molt: instances/rhadamanth and instances/gyges ssh/config.d/lan-hosts.conf name hosts as <host>.lan in both Host and HostName. They still work while the router answers .lan, but they are a second place the house domain is written. Whether those fragments should be rendered from the same setting is part of hv's ruling (Highlander).

This touches the same generator as issue 0041, so they can be built together.
