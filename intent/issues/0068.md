The dev/opt/brew contract (devbin's `docs/dev-opt-brew.md`, the `use brew` bullet of T5) gained amendment A4 in devbin-vc's round on 26 Oct 2026, worded as intent-vc's counter. `use brew` must refuse, removing nothing, when no Homebrew copy would answer once its links are gone, whether the formula is not installed, its keg is not linked or another copy comes first on PATH. The refusal names each link and the tree it serves, why no Homebrew copy would answer, and the tool's own remedy. Each tool conforms in its next release.

`molt use brew` does not conform. `_molt_use_root brew` finds the brew tree by the formula's opt link, `$(brew --prefix)/opt/molt/libexec`, and Homebrew keeps that link for an unlinked keg. So with the keg unlinked, `cmd_use` passes its `-x $root/bin/molt` check, `_molt_use_remove_link` removes `~/.local/bin/molt`, and only then does `_molt_use_shadow_fault` report that no molt is on PATH. That leaves no molt to run. With another molt ahead of brew's bin, the same order leaves that copy answering. When the formula is not installed, it does refuse before removing, but the refusal names neither the link nor the tree it serves.

To conform, `molt use brew` first works out what PATH would run once `~/.local/bin/molt` is gone. That is the first molt on PATH, skipping the link's directory, with directories compared where they resolve, since rhadamanth's `~/bin` is `~/.local/bin`. It refuses unless that molt resolves into the brew tree. The refusal names:
- the link and the tree it serves;
- why no Homebrew copy would answer: the formula is not installed, the keg is not linked, or another copy comes first on PATH, named by path;
- the remedy: `brew install` or `brew link` molt, move that copy aside, or stay on dev or opt.

Tests cover each cause the contract names, and each shows the link still in place after the refusal.

Molt 1.1.0 is out, so this ships in Molt's next release.


## As built (cc, 30 Oct 2026; merged by vc at 771c51f)

- `molt use brew` asks `_molt_use_brew_fault` before anything is removed, whenever a link exists. It works out what PATH would run without `~/.local/bin/molt`: the first molt outside the link's directory, compared where they resolve (rhadamanth's `~/bin` is `~/.local/bin`), which must resolve into the brew tree, as `molt_brew_on_path` asks.
- The refusal reads `~/.local/bin/molt is left in place (it serves the <tree> tree at <root>), as no Homebrew molt would answer once it is gone: <cause>, or stay on dev or opt`. Each cause names its remedy: the formula is not installed (`brew install matthewsinclair/molt/molt`), its keg is not linked (`brew link molt`), or `<path>` comes first on PATH and is not Homebrew's (move it aside).
- With no link, `use brew` is unchanged.
