`molt resleeve` can report what did not happen, in two ways.

1. `bin/molt:136` counted failures with `((failed++))`. From 0 that expression returns 1, and under `set -e` bash 4.1 and later end the script there: resleeve stops at the first liberator failure, runs none of the rest, and never prints the failure count. bash 3.2, the one CI's macOS runner has, carries on, so CI could not see it. Even when it did carry on, resleeve exited 0 after a failure.
2. `molt_link` in `lib/molt.sh` did not check its `mv`, `rm`, `mkdir` and `ln` steps. Its callers run it inside `if` and `||`, where `set -e` does not apply, so a failed step ran on to "Linked:" and returned 0.

Fix: count with `failed=$((failed + 1))` and return 1 when anything failed; check each `molt_link` step and return 1 with a `molt_error`. One pinning test each in `test/molt.bats`. critic-shell then found the liberators calling `molt_link` partway through an install without checking it (16 sites, eg `zsh_install`), so the failure was still lost and resleeve still printed "installed"; each now has `|| return 1`.
