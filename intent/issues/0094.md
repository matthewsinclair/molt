`molt doctor`'s "Checking declared font" resolves the instance's `MOLT_FONT_FAMILY` with fontconfig. It counts no declaration, a font that is not installed, or no `fc-list`, as not passed. Under WSL2 the terminal is Windows Terminal, on the Windows side. So a font installed in Ubuntu proves nothing about the glyphs a participant sees, and a font missing there does no harm. A participant's laptop cannot pass the check honestly.

Found while reading Molt for pipeliner-sc's ask of 5 Nov, whether Molt can resleeve a WSL2 Ubuntu for hv's bootcamp. molt-vc's answer is `/Users/matts/Devel/scratch/molt-vc/answer-pipeliner-sc-2026-11-05.md`. Filed on hv's word, relayed by devbin-vc on 5 Nov.

The change: doctor recognises a sleeve whose terminal Windows draws, either from a declaration in its instance or by detecting WSL as devbin's `is_wsl` does. The font check then says the font is the Windows side's to provide, instead of failing. The design settles how that counts, given hv's ruling of 23 Oct that a check that could not measure is not a pass. Size XS.

It is made once the course plan settles whether `molt doctor` is the first-run script's proof, and not before.

## As built

Merged at 4116a1b, from b83c880 on `dc/doctor-participant`.

- `MOLT_TERMINAL_DRAWN_BY` is read through `molt_instance_var` from the instance's `vars.sh`. Set to `windows`, it makes the font check pass without asking fontconfig, printing `Checking declared font... ✓ Windows draws this terminal, so its font is the Windows side's to provide`. Any other value is reported and does not pass, so a typo neither passes nor falls back quietly. Without it, the check is as it was. It is a declaration, not WSL detection: molt does what its config says.
- The new-user skeleton's `vars.sh` names it among what molt reads, as do `docs/guides/templates.md`, the bootstrap runbook and `docs/guides/getting-started.md`.
