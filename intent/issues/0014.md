Found by kovacs-sysadm reading `liberators/tiling.sh` on 16 Oct. Nothing has broken yet: Tactile 38 is active on GNOME Shell 50.1, and its schema in `/usr/share/glib-2.0/schemas` matches the extension's own, because kovacs had no copy there before the 14 Oct install.

- `tiling_install` copies the extension's gschema into `/usr/share/glib-2.0/schemas` only when no copy is there. After a Tactile update every run keeps the old one, and molt's gsettings writes go through it.
- The `sudo cp`, the `sudo glib-compile-schemas` and every `gsettings set` are unchecked, so install says "Liberator complete" even when all of them failed.
- check and verify cannot see a stale schema.
- The install hint pins `version_tag=65140`, one extensions.gnome.org build, whatever shell the sleeve runs.

Fix: install refreshes the system copy whenever it differs from the extension's, and fails when the copy, the compile or any setting fails. check and verify report a copy that differs. gsettings reads the compiled database, not the XML, so the extension's schema is compiled under `--strict` before it is copied, and a copy the system compile rejects is taken back out; otherwise the next check would find the XML matching and pass. A `cmp` that cannot compare is reported as unknown, not as a difference. The hint asks extensions.gnome.org for the build that fits the running shell.
