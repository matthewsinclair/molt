## What happens

The user-scope status line Molt-matts declares (`config/claude/statusline.json`) ends in `exec npx -y ccstatusline@2.0.12`. npm's cache defaults to `~/.npm`, so every status-line refresh repopulates `~/.npm/_npx/<hash>/node_modules/ccstatusline`, `_cacache`, `_logs` and `_update-notifier-last-checked`, on every sleeve that runs Claude Code. kovacs, 21 Oct 2026, ST0006 WP04 C3: hv removed `~/.npm` as an npm-era leftover at 23:03 and it was back at 23:03:19; `verify-wp04.sh c4` fails on it alone. rhadamanth's `~/.npm` is the same: three `_npx` copies of ccstatusline, `_logs` written at 23:08 tonight, `npm config get cache` answering `/Users/matts/.npm`.

So a directory ST0006 set out to keep out of `$HOME` is written there by Claude Code's own child, and nothing in Molt says where it should go. hv's rulings (21 Oct): the cache moves under XDG, through Molt, and everywhere, not only on a sleeve whose Claude Code state has moved.

## Expected

A new `npm` liberator (`liberators/npm.sh`) keeps npm's cache out of `$HOME` on every sleeve, by the one setting npm reads however it is started, from a terminal or a GUI child, with no environment and no re-login: `~/.npmrc`.

- `templates/npm/npmrc.tmpl`, a framework template like `templates/claude/`: its first line carries the `@@MOLT:BEGIN@@` marker as a `#` comment (ini comments), then `cache=${MOLT_NPM_CACHE_DIR}`. The liberator computes `MOLT_NPM_CACHE_DIR="${XDG_CACHE_HOME:-$HOME/.cache}/npm"` at render time and exports it for envsubst (only `MOLT_*` names are substituted), as the claude liberator does for the agents root. `~/.cache/npm` sits beside the native installer's `~/.cache/claude` on both macOS and Linux.
- Hand lines above the marker are kept, as `molt_render_place` keeps them for `~/.ssh/config`: rhadamanth's `~/.npmrc` holds hv's `allow-scripts=...` line and must come through with it, above the marker, with the one backup a first render over a regular file takes. Mode 600 after the render, since an npmrc can hold a registry token.
- `npm_check`: with no `npm` on PATH, `molt_info "npm: npm is not installed, so there is nothing to configure"` and pass, so farcaster and pihole carry the liberator without a file they do not need; otherwise `molt_render_stale` on `~/.npmrc` against the template says installed or not, and when `~/.npm` exists an info line says it is the old cache, left for the user to remove once `~/.npmrc` names the new one (nothing in Molt removes it: it is data). `npm_install`: render. `npm_verify`: with npm installed, `npm config get cache` answers the rendered path, which proves npm reads the file; without npm, pass saying nothing was checked, as other liberators do for an absent tool.
- Molt-matts: `[[liberator]] name = "npm"` in every instance manifest (rhadamanth, gyges, kovacs, farcaster, pihole), after `dev-tools`.
- CHANGELOG: an Added line ending `(issue 0031)`. The guide (`docs/guides/sleeve-agents.md`): one sentence where the homes' cleanliness is described, naming `~/.npmrc` and why.

npm reads `npm_config_*` environment names case-insensitively too, but a variable reaches only the processes whose ancestors exported it, and this sleeve's env.sh exists only once Claude Code's state has moved; `~/.npmrc` reaches every npm on the sleeve from the next run. `_npx`, `_cacache` and `_logs` all live under the cache dir, so the one setting moves all of it.
