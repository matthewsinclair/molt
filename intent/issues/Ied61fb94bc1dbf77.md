## What is broken

`editors_upgrade` pulls the Doom config repo that `editors_repo` finds (liberators/editors.sh:5 and :315). When `~/.config/doom` links into the user stack, eg Molt-matts `config/doom`, `editors_repo` returns that directory, and `molt_git_pull` (lib/molt.sh:2780) pulls the whole stack repo.

This is a second pull of the stack in one upgrade. The stack's own pull is in `_upgrade_pull_repos` (lib/molt.sh:2851), which first checks that the stack is clean. The editors pull has no clean check, and `--no-pull` does not skip it: lib/molt.sh:3184 skips only `_upgrade_pull_repos`.

## What it costs

On rhadamanth, 2026-11-25, in the v1.4.13 rollout, Molt-matts held six uncommitted files of hv's. `molt upgrade` refused, as it must. `molt upgrade --no-pull` then ran every hook and the resleeve (24 liberators, none failed), but git refused the editors hook's pull of the dirty stack, so the upgrade exited 1. rhadamanth-sysadm found it.

## What fixes it

The editors hook pulls only a Doom config repo of its own. When the Doom config's repo is the user stack, the hook skips the pull, because `_upgrade_pull_repos` owns that pull and its clean check (Highlander). `--no-pull` keeps its meaning: the restart (lib/molt.sh:3091) runs with it, and the hooks' own pulls must still run there.
