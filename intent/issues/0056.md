## What happens

On Linux the env writer publishes a GUI PATH that is missing the system's own entries. `_molt_env_login_path` (lib/env.sh:146-159) reads PATH from `env -i HOME USER LOGNAME SHELL TERM=dumb zsh -lic`. With an empty environment, zsh starts from its compiled default, `/bin:/usr/bin:/usr/ucb:/usr/local/bin`. On Ubuntu the session PATH comes from PAM's `/etc/environment`, not from any zsh startup file, so the login shell never gets it.

kovacs-sysadm read kovacs's `~/.config/environment.d/molt.conf` after hv's `molt resleeve` on Molt 1.0.0 from brew (24 Oct, 21:41 local):

```
/home/matts/.local/bin:/home/linuxbrew/.linuxbrew/bin:/home/linuxbrew/.linuxbrew/sbin:/bin:/usr/bin:/usr/ucb:/usr/local/bin:~/.cargo/bin:~/bin:~/.config/emacs/bin
```

`/usr/sbin`, `/sbin`, `/usr/local/sbin`, `/usr/games` and `/snap/bin` are all missing, and `/usr/ucb`, which does not exist on Linux, is included. Starting with the next login, apps launched from the desktop get this PATH, so they can't find snap commands or sbin tools by name. `molt doctor` passes, because it compares env.sh and molt.conf against a fresh read made the same way.

macOS is not affected: `/etc/zprofile` runs `path_helper`, which rebuilds PATH from `/etc/paths` and `/etc/paths.d` inside the login shell.

## Fix

The login-shell read starts from the platform's base PATH, not zsh's compiled default.

- **On Linux,** seed the `env -i` with `PATH` from the `PATH=` line of `/etc/environment` when that file has one. The file is named once, through a variable that tests can point at a fixture. With no such line, keep today's behaviour and say so.
- **On macOS,** change nothing: `path_helper` already does this job.
- **Never seed from the caller's own `$PATH`.** That would carry whatever shell ran molt into launchd and environment.d. The point of `env -i` is that it doesn't.

## Tests

- A fake `/etc/environment` and a fake login shell that echoes the PATH it was given. Assert that the published PATH starts from the file's entries, with ~/.local/bin first, and that `/usr/ucb` is absent.
- Assert that no `/etc/environment` means today's behaviour.
- Build the expected values independently. Run under both bashes.
