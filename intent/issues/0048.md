On macOS, when `code` is not on PATH, vscode_install links Visual Studio Code's CLI into a hardcoded `$HOME/bin` (liberators/vscode.sh, `mkdir -p "$HOME/bin"` and `ln -sf ... "$HOME/bin/code"`). Molt's own bin directory is MOLT_LOCAL_BIN (lib/constants.sh, default `~/.local/bin`), and molt's own link lives there. The vscode liberator ignores it.

What this means, by sleeve:

- The branch runs on macOS only, so kovacs and the other Linux sleeves never reach it.
- On rhadamanth, `~/bin` and `~/.local/bin` are one directory under two names, so today the link lands where molt's does.
- On a Mac where they are different directories, `code` goes to a directory that may not be on PATH. Install still says "Symlinked 'code' CLI to ~/bin/code", and the next check fails the same way. gyges's layout has not been checked.
- The `ln -sf` status is not checked either, so a failed link is reported as made.

Fix to decide (hv):
- Link `code` into MOLT_LOCAL_BIN, as molt links itself, check the `ln` status, and leave an existing `~/bin/code` alone or remove it.
- Moving where the link lives changes a path outside the liberator's contract, so it waits for hv's go.
