## Design (B)

A value fixed when `molt upgrade` renders would go stale at the next login after a `ccusage use`, and Molt's doctor would fail after every switch. So the value is read where it is used, from one definition:

1. The env writer, `lib/env.sh`, takes a third scope beside `all` and `gui`: `command`, whose value is a command line, each word quoted by the writer. The variable is what the command prints, read at each shell start by env.sh and at each login by the LaunchAgent; nothing is set when the command fails or prints nothing. environment.d cannot run a command, so a Linux sleeve's GUI file leaves it out. The session check leaves the value to the tool that owns it, so doctor never fails on a switch.
2. The claude liberator gives `CLAUDE_SECURESTORAGE_CONFIG_DIR` as a command pair, ccusage's absolute path and `dir`, on a sleeve where ccusage is on PATH and `CLAUDE_CONFIG_DIR` is published.

The shell half comes through env.sh, which `~/.zshenv` sources already, so Molt-matts needs no line of its own, and env.sh and the agent cannot drift apart. Both halves do nothing until hv's step 1 turns shared mode on.
