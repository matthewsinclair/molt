Found by vc 2026-09-08 (hv/inbox.vc.md), extended against the live tile 2026-09-15.

1. Absent recentRuns is reported as fact that no backup exists: backup.sh:323 "has never completed a copy -- no backup exists yet", backup.sh:416 "no backup exists". A job that is recreated loses its run history without losing its backup, so the tile cannot support that claim. hv corrected exactly this inference on 2026-09-08.

2. A failed latest run hides the last good copy. Live on rhadamanth 2026-09-15: last success 01:59Z, then six non-successful attempts (CANCELLED x2, FAILED x3, DESTINATION_NOT_CONNECTED), latest 07:59Z FAILED ("hdiutil: isencrypted failed - Resource temporarily unavailable"). Check and verify say only "last copy did NOT succeed"; neither says whether or when a successful backup exists.

3. Highlander: the run-history evaluation is duplicated between backup_check (:303-329, distinguishes CANCELLED) and backup_verify (:404-422, does not), so the two already disagree and any message fix would have to be made twice.

Fix: one evaluator used by both; report the latest outcome AND the age of the latest success; word absent history as unknown, not as no backup. Pass/fail semantics unchanged: a failing latest run still fails.
