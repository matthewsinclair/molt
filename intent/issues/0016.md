Found by critic-shell while reviewing the fix for issue 0013 on 16 Oct.

`molt_log` echoes every level to stdout, `molt_error` included. A function that reports through it and is called as `x="$(fn)"` hands its diagnostics to the caller's variable rather than to the user. `molt_find_user_repo` is the clearest case. When it finds no repo it prints what it searched and how to set `MOLT_PRJ_DIR` and `MOLT_CFG_DIR`, but every caller captures it, and the ones read on 16 Oct drop what they capture. So someone without a config repo sees only "Cannot resleeve without a user config repo." The `2>/dev/null` many call sites add has no effect on this, because the text was never on stderr.

The fix that reaches every site at once is to send error lines to stderr. That changes what every captured call collects, so it needs its own pass with the call sites read, not a drive-by edit.
