bootstrap.sh's usage advertises `curl -fsSL <raw-url>/bin/bootstrap.sh | MOLT_PRJ_DIR=~/Devel/prj bash`. Piped that way, the script's stdin is the script itself. The final `read -rp "Run molt resleeve now? [y/N] "` then reads the script's next line as its answer, so resleeve's prompt is answered by source text rather than the person, and bash is left mid-script, so the `else` becomes a syntax error. ac reproduced it on /bin/bash 3.2. The `ssh -T git@github.com` probe in git_url has the same exposure: ssh reads stdin and can swallow the rest of the piped script.

Fix: read the answer from /dev/tty, and refuse by name when there is no terminal to ask. Give the ssh probe `-n` so it never reads stdin.

Found by ac's docs review; vc checked it.
