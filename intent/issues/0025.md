## What happens

`molt_instance_var` sources this sleeve's vars.sh in a subshell and prints the value, followed by a closing line, `molt: read to its end`. A sourcing that ends early is caught because the closing line is not last. An EXIT trap in vars.sh runs when that subshell exits, which is after the closing line. When the trap writes to stdout, its output comes after the closing line. `molt_instance_var` then reports "<vars.sh> stops before its end when sourced" with status 2, though the file was sourced to its end.

`molt_instance_vars_fault` has the same blind spot for a trap that writes to stderr: its probe reads the last line of stderr as the file's own error, so `trap 'echo bye >&2' EXIT` makes the fault report the same "stops before its end". That refuses molt_render as well as molt_instance_var.

`molt_render_text` already keeps such a trap's output out of its failure reason (templates.bats), so a vars.sh that renders fine is refused by the `MOLT_AGT_DIR` check that `agents install` runs through molt_instance_var. The two readers disagree about the same file.

## Repro (main at bea7420, bash 5 and /bin/bash 3.2)

Use a user repo with `config/`, `instances/h/vars.sh`, and `molt_hostname` stubbed to print `h`.

| vars.sh                                       | molt_instance_vars_fault   | molt_instance_var FOO          |
| --------------------------------------------- | -------------------------- | ------------------------------ |
| `export FOO=bar`                              | (none)                     | rc 0, `bar`                    |
| `export FOO=bar` + `trap "echo bye" EXIT`     | (none)                     | rc 2, "stops before its end"   |
| `export FOO=bar` + `trap "echo bye >&2" EXIT` | "stops before its end"     | rc 2, "stops before its end"   |
| `export FOO=bar` + `trap ":" EXIT`            | (none)                     | rc 0, `bar`                    |

## Severity

The severity is low. A vars.sh is a file of exports, and an EXIT trap that prints is unusual. Still, the message is false: it names a file that did source to its end. The fix is not made yet; vc is queueing it.
