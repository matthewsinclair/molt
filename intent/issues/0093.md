`molt doctor`'s "Checking GitHub auth" always runs `ssh -T git@github.com` (`molt_github_auth_check` in `lib/molt.sh`), and `molt_github_auth_verdict` counts anything but GitHub's "successfully authenticated" reply as not passed. So a sleeve whose stack reaches only a GitLab host, as a bootcamp participant's laptop would, can never read "All checks passed".

Found while reading Molt for pipeliner-sc's ask of 5 Nov, whether Molt can resleeve a WSL2 Ubuntu for hv's bootcamp. molt-vc's answer is `/Users/matts/Devel/scratch/molt-vc/answer-pipeliner-sc-2026-11-05.md`. Filed on hv's word, relayed by devbin-vc on 5 Nov.

The change: doctor checks the git hosts the stack's ssh config names, rather than GitHub alone. It checks each by its own reply (GitHub's "successfully authenticated", GitLab's "Welcome to GitLab"), and says which hosts it checked. Size S.

It is made once the course plan settles whether `molt doctor` is the first-run script's proof, and not before.

## As built

Merged at 4116a1b, from 4176036 on `dc/doctor-participant`. Built on hv's word of 5 Nov to fix it now.

- A git host is an entry in molt's region of `~/.ssh/config` that sets `User git` itself. That region is the template's section and the `config.d` fragments after it. Doctor dials each as `git@<name>`, and it passes on GitHub's or GitLab's own reply naming the user. A reply doctor does not know is shown and not passed. The code is `molt_git_hosts`, `molt_git_host_verdict` and `molt_git_hosts_check` in `lib/molt.sh`.
- With no git host to dial, the check passes, saying which of three it found: no ssh config, no molt region in it, or no `User git` entry there. A stack that reaches GitLab only over HTTPS, as the bootcamp's course template does, passes on the last.
- Issue 0069's bounds hold per host, as `MOLT_GIT_HOST_CONNECT_TIMEOUT` and `MOLT_GIT_HOST_TIMEOUT`, renamed from `MOLT_GITHUB_*` with no alias. Doctor tests with no ssh fixture now dial nothing, where they ran the real ssh.
- The tests are in `test/molt.bats`, red at the base and green at the fix under both bashes. The file passed whole at the final head, 95 of 95 under each. `README.md` and `docs/guides/getting-started.md` say so.
