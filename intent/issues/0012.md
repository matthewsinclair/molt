The generated iTerm2 ssh wrapper reset a tab to `000000` when ssh returned, whatever the sleeve's own background was. rhadamanth's profile background is `#15191F`, so a tab came back from ssh blacker than it started. xterm's OSC 111 reset does not undo iTerm2's `SetColors` (hv tested it on 15 Oct: the tab stayed red), so the colour has to be declared.

Fix: a new `[terminal] bg_color` field in each sleeve's `instances/<host>/instance.toml` in the user repo, read through `molt_instances_field`. The wrapper resets to the local sleeve's `bg_color`, or to `000000` when the sleeve declares none. Molt-matts declares `15191f` for rhadamanth.
