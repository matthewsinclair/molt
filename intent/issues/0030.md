## What happened

kovacs, 21 Oct 2026, ST0006 WP04 B9. `molt resleeve` moved Claude Code's state into `~/.config/claude` at 22:29:04 and wrote `~/.config/molt/env.sh` and `~/.config/environment.d/claude.conf`. At 22:29:09 hv ran `claude --name kovacs-sysadm` from the agent home, in a terminal opened at 22:27, before env.sh existed. The process had no `CLAUDE_CONFIG_DIR` (its `/proc/<pid>/environ` shows none), so Claude Code started fresh in `$HOME`: new `~/.claude` and `~/.claude.json` (`firstStartTime` 22:29:10, `numStartups` 1), a second login, plugins re-fetched, the session's transcript under `~/.claude/projects/`. The moved state in `~/.config/claude` was untouched and unread.

The home guard did not run. It is a UserPromptSubmit hook in the user-scope settings (`templates/claude/home-guard-hook.json`, merged by `liberators/claude.sh` into `<config dir>/settings.json`), and that file lives in the config dir the launch missed. The fresh `~/.claude/settings.json` had no hook. So the one launch fault the move makes likely, a stale shell, is the one the guard cannot see by construction. `molt doctor` names the condition afterwards (`~/.claude and ~/.claude.json are present while the config dir is ...: a launch path missed CLAUDE_CONFIG_DIR, or a move did not finish`), which is how it was found, after the state had diverged and a token had been issued.

## Expected

The launch is refused at the first prompt, before anything is written that has to be reconciled. The agent home's own `.claude/settings.json` is project scope, read from the launch directory whatever config dir the process uses, and the agents liberator already shapes that file with jq after rendering (`_agents_memory_dir_set`, `liberators/agents.sh:12`). So:

1. `liberators/agents.sh` also merges the home guard's hook entry (the same `templates/claude/home-guard-hook.json`, the same `~/.config/molt/claude-home-guard.sh`, which lives outside the Claude config dir and so is present whichever one the process read) into each rendered home `settings.json`, in the same way `_claude_settings_merge` does for the user scope, so one script and one hook JSON serve both scopes (Highlander). Running twice in a home, once per scope, is a few milliseconds of sh and is accepted.
2. `templates/claude/claude-home-guard.sh.tmpl` gains a third test. The config dir molt rendered it with is read from a second quoted here-document, like `MOLT_AGENTS_ROOT`, carrying `${MOLT_CLAUDE_CONFIG_DIR}`. When that line is non-empty and the hook's `CLAUDE_CONFIG_DIR` is empty or names a different directory (compared as the disk spells them, with `real_dir`), exit 2 with a line such as `this Claude Code did not get CLAUDE_CONFIG_DIR (want ~/.config/claude): quit it, open a new shell, or log out and in, and relaunch from the home`. A sleeve with no declaration renders an empty line and skips the test, as the agents-root test skips an empty root. Hooks inherit the process environment, so the hook sees exactly what the process saw.
3. `liberators/claude.sh`'s drift check (`_claude_guard_agt_dir`, `:456-471`) reads the config-dir line the same way, so a guard rendered before the declaration, or with another dir, reports drifted and re-renders on the next upgrade, as the agents-root line does today.
4. `molt agent config` shows the home's hook as it shows the fence and the memory dir, so a home without it reads as a fault, not current.

## Tests
