# ST0004: Intent liberator: install from Homebrew, hands off rhadamanth

## Objective

Molt's intent liberator installs and checks Intent the way an everyday user gets it, from Homebrew, and its verdict names the Intent that `intent` actually runs. Molt stops managing Intent on rhadamanth, the machine Intent is developed on.

## Context

On 23 Sep 2026 gyges's `molt upgrade` warned that PATH resolves `intent` to `/opt/homebrew/bin/intent`, not `~/bin/intent`, and still printed `intent: ✓ ok`. Measured on gyges the same morning: the link Molt managed pointed at Intent 2.6.0 (the v2 script in a frozen, pre-rewrite checkout), login shells ran Homebrew's 3.2.0, and an interactive non-login shell ran 2.6.0. The check never asked which version it had linked, and its shadow warning went quiet in exactly the shell where v2 ran. v2.6.0 refuses a v3 project with an error and writes nothing, so nothing was damaged.

hv's rulings the same day: gyges is the test bed for running Intent from brew like an everyday user, with no local copy of the dev tree, and problems with that go to intent-vc. Nothing to do with Intent on rhadamanth may be touched. Do just enough to prove it works.

The liberator's source-checkout mode had two intended users. rhadamanth is now off limits, and kovacs has no Intent and does not list the liberator. So the liberator becomes brew-only rather than keep a mode that no machine runs.
