# ST0008: Molt from brew: dev, opt and brew trees

## Objective

A sleeve runs Molt from one of three trees, and says which: **dev**, the git checkout (on rhadamanth, `~/Devel/prj/Molt`); **opt**, an install published from a clean checkout to a prefix the sleeve declares; and **brew**, the `matthewsinclair/molt/molt` formula's keg. `molt use [dev|opt|brew]` switches the tree `~/bin/molt` serves, and `molt version` names the tree that answered. This lets hv work on Molt in the dev tree on rhadamanth and test a change there without a brew install, while the sleeve's everyday `molt` runs from opt or brew, so the shared checkout's live board views no longer make `molt upgrade` refuse. kovacs runs brew only; gyges moves to brew only over time; farcaster and pihole keep a dev tree.

## Context

hv, 24 Oct: "we need a way (esp on rhad) to run in dev mode and have the dev/opt (and maybe now 'brew', too?) switch functionality that devbin offers. This is important so that I can work on it here on rhad and not have to go thru a whole brew install just to test it. kovacs stays brew only, and we move gyges to brew only, too, over time."

hv's other rulings, same session: the formula lives in a new public tap, `matthewsinclair/homebrew-molt`, beside the utilz, devbin and intent taps; and on a brew sleeve `molt upgrade` runs `brew upgrade matthewsinclair/molt/molt` itself and restarts on the new version, as it restarts after a pull today.

Prior art, to follow rather than reinvent: Utilz's `utilz install` / `utilz use dev|opt` / `utilz relink` (Utilz `README.md`, "Two trees: dev and opt"), and devbin's formula template with `formula render|publish` (`packaging/homebrew/`, `docs/releasing.md`). Both publish with `--prefix <dir> --managed-by brew` from inside the formula, both refuse to publish from a dirty tree, and both refuse their test suite inside an install.

Why now: rhadamanth's `molt upgrade` refuses while the shared checkout carries uncommitted board views, because the framework repo is the dev tree (`_upgrade_check_clean "$MOLT_ROOT"`, `lib/molt.sh`). The design is in `design.md`.
